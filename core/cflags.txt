# Core compilation flags. The ONLY place they are defined.
#
# Read by both the Makefile (M0) and core-sys/build.rs (from M1, step D1 in
# ROADMAP.md). A mismatch between the two builds silently breaks determinism --
# PROJECT.md section 4. Lines starting with # are ignored.

-std=c11

# Warnings are errors. PROJECT.md section 9.
-Wall
-Wextra
-Werror

# Not below -O1. At -O0 gcc calls sqrt as a libm function instead of the
# hardware instruction, and the determinism scenarios, which deliberately link
# without -lm, fail to link. So "build unoptimised for debugging" does not work
# here -- use -O1 -g, the result is bit-identical (measured, ROADMAP C5).
-O2
-g

# Determinism. Forbids the compiler from fusing multiply and add into FMA:
# otherwise the same source gives different bits on different platforms.
# -ffast-math NEVER, under any circumstances. PROJECT.md section 4.
-ffp-contract=off

# Lets the compiler skip the libm call made for errno and take the hardware
# sqrt directly. Without it sqrt does not link (we deliberately do not link
# -lm), and with -lm all of libm would seep into the core.
#
# Does NOT affect bitwise accuracy: IEEE-754 requires correctly rounded sqrt,
# so the value is the same and only the errno write disappears. This is its own
# flag, not part of -ffast-math in the reassociation sense -- it permits none.
-fno-math-errno

# Measured (ROADMAP C5): every scenario hash is BIT-identical at -O1, -O2, -O3,
# -Os, -march=native and -funroll-loops. That is, the core holds nothing the
# compiler could reassociate -- and with -ffast-math the hashes do diverge, so
# the check has teeth rather than merely agreeing with itself.
