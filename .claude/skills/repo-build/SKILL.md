# repo-build

Немає CMake свідомо (CLAUDE.md: «додамо, тільки якщо `/core` знадобиться
окремо від Rust»). Одна команда `cargo build` збирає все, включно з C —
через крейт `cc` у [core-sys/build.rs](../../core-sys/build.rs).

## Дві збірки C, одне джерело прапорців

`Makefile` (для `/core` окремо, юніт-тести C) і `core-sys/build.rs` (для
Rust) **обидва** читають [core/cflags.txt](../../core/cflags.txt) і
більше нізвідки. Це навмисно: якщо прапорці продублювати в двох місцях,
розбіжність між ними не впаде і не попередить — вона тихо змінить
останні біти результату (PROJECT.md §4, детермінізм). Якщо колись
здається, що треба додати прапорець «просто для Rust-збірки» — не варто,
він має піти в `cflags.txt`, інакше `make test` і `cargo test` почнуть
бачити різне ядро.

`-fPIC` — єдиний прапорець поза цим файлом (потрібен для Rust-лінковки,
не для C-юнітів; на Windows не застосовний, тому плоский спільний список
його не виражає).

## Workspace

[Cargo.toml](../../Cargo.toml) — члени додаються **в міру появи коду**,
не наперед (порожній крейт у `members` ламає збірку без користі).
Поточний склад: `core-sys`, `core-rs`, `engine`, `tools/gpu-probe`,
`tools/slang-probe`. `game/` і `tools/` (окрім двох розвідок вище) — ще
порожні, у workspace не додані.

`rust-version = "1.87"` — вимога `wgpu` 30. Канал — **stable**, не
закріплена патч-версія: відтворюваність проєкту живе в хешах сценаріїв
C-ядра, не в точній версії rustc, і закріплювати її означало б
обслуговувати те, що ні на що не впливає ([rust-toolchain.toml](../../rust-toolchain.toml)
читає лише `rustup`; системний `cargo` з apt його не бачить і збере
мовчки не тим — README.md, «Версія Rust», має точний спосіб перевірити,
чий саме `cargo` в `PATH`).

`[workspace.lints.clippy] all = "deny"` у `Cargo.toml` — групи clippy тут;
«попередження компілятора = помилки» вмикається окремо в CI через
`-D warnings`, не в маніфесті: `deny(warnings)` заважав би саме тоді,
коли код ще пишеться (незакінчена думка = помилка компіляції).

## Команди

```sh
make test                          # усе про C: check-libm, юніт-тести, звірка хешів детермінізму
make csv && make plots             # діагностичні графіки (потрібен matplotlib)
make flags                         # прапорці ядра з боку Makefile

cargo build --workspace            # усе, включно з C через build.rs
cargo test --workspace
cargo clippy --all-targets -- -D warnings   # той самий гейт, що в CI
cargo run -q --example flags       # ті самі прапорці, з боку cargo — має збігатися з `make flags`
```

Усі команди — **з кореня репозиторію**: тести й експортери читають
`data/`.

## Коли оновлювати цей скіл

- Змінився склад `[workspace] members` у `Cargo.toml` — онови список.
- Змінилась вимога `rust-version` (вона піде вгору разом із залежностями
  на кшталт `wgpu`, як уже було 1.75→1.87) — онови число й причину.
- З'явився CMake або інший спосіб збірки `/core` окремо — це порушення
  поточного інваріанта «без CMake», тобто свідома зміна, яку варто
  відзначити тут явно.
- Прапорець потрапив у `build.rs` чи `Makefile` напряму, а не в
  `cflags.txt` — це вже помилка, яку варто зловити на рев'ю, а не
  привід міняти цей скіл.
