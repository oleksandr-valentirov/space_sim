# core-physics

Стан на момент запису: **Milestone 0 закрито** (етапи A–C), межа C↔Rust
закрита двічі — етап D (ефемерида) і етап H (пропагатор, `prop.c`, з
подіями). Сама фізика в `/core` з D3 не зупинялась: C4 (повна ефемерида),
shooting/station-keeping і M3.5-заготовки (`field.c`) уже в коді. Перш ніж вважати щось "не зробленим", перевір файл, а не лише
ROADMAP.md — нижче список того, що реально є.

Джерело істини — [PROJECT.md](../../PROJECT.md) §4 (фізична модель) і §9
(стиль C). Цей файл — покажчик по коду, не заміна.

## Жорсткі інваріанти (тут, а не тільки в CLAUDE.md)

1. **У циклі інтегрування — лише `+ - * /` і `sqrt`.** Жодного `libm`:
   `sin/cos/exp/pow/atan2` бітово не гарантовані між платформами. `richardson.c`
   і `station.c` явно документують, чому в них теж немає `libm`, хоч це
   рантайм-код планування, не пропагація.
2. **`-ffp-contract=off`, ніякого `-ffast-math`.** Прапорці — в
   [core/cflags.txt](../../core/cflags.txt), **єдине місце**: і `make`, і
   `core-sys/build.rs` читають рівно його. Розбіжність між ними — це не
   помилка компіляції, а тиха зміна останніх бітів.
3. **Без `-lm`.** `-fno-math-errno` дозволяє апаратний `sqrt` без лінковки
   libm; сценарії детермінізму лінкуються без `-lm` навмисно як "поліція
   libm" (`make check-libm`) — якщо хтось випадково викликав функцію з libm,
   лінковка впаде.
4. **Один інтегратор, один допуск для прогнозу й фізики** (CLAUDE.md
   інваріант 5) — `dop853_integrate_blocks` з цієї ж причини носить STM
   разом з траєкторією, а не окремим проходом.
5. **Без глобального стану, без алокацій у гарячому циклі** (CLAUDE.md,
   «Стиль C»).

## Тести й перевірка

```sh
make test              # check-libm + unit (core/test/*.c) + determinism (хеш проти core/scenario/golden.txt)
make csv && make plots # діагностичні графіки з build/csv/*.csv (потрібен matplotlib)
make cook               # перегенерувати ассет-фікстуру — робити свідомо, воно комітиться
make flags               # прапорці, якими компілюється ядро — звірка з тим, що бачить cargo
```

Юніт-тести — `core/test/test_*.c`, кожен окремий бінарник (`core/test/test.h`
— мінімальний харнес). Сценарії детермінізму — `core/scenario/sc_*.c`,
еталон — `core/scenario/golden.txt`; `make determinism-bless` перегенеровує
еталон свідомо, коли зміна хешів — очікувана.

Тест на нестійкість (`test_stability.c`) — не «показник поганого коду»:
halo-орбіти лінійно нестійкі за конструкцією, і зростання збурення там —
вимірюваний факт (показник Ляпунова), а не привід шукати баг.

## Коли оновлювати цей скіл

- Змінився публічний інтерфейс будь-якого `core/*.h` (нова функція, інша
  сигнатура) — онови таблицю файлів вище.
- ROADMAP.md позначив новим ✅ крок етапу K. Лишились K7b (опір у полі,
  ассеті й на межі) і K5 (маскони, потребує нормованої рекурсії) — кожен
  змінить рядок `field.c/h` або `harmonics.c/h`, і кожен стане **першим
  справжнім читачем** `eph_body_orientation`: сам K3b обертання в поле не
  завів, бо зональному полю досить полюса.
- Змінився `core/cflags.txt` — звір розділ «Жорсткі інваріанти» з файлом
  напряму, не покладайся на цей опис.
- З'явився новий `core/scenario/sc_*.c` або `core/test/test_*.c` —
  необов'язково описувати кожен, але якщо він перевіряє новий інваріант
  (не просто ще один сценарій для регресії), варто рядок сюди додати.
