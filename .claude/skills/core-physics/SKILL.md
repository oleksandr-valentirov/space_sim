# core-physics

Стан на момент запису: **Milestone 0 закрито** (етапи A–C), межа C↔Rust
закрита двічі — етап D (ефемерида) і етап H (пропагатор, `prop.c`, з
подіями). Сама фізика в `/core` з D3 не зупинялась: C4 (повна ефемерида),
shooting/station-keeping і M3.5-заготовки (`field.c`) уже в коді. Перш ніж вважати щось "не зробленим", перевір файл, а не лише
ROADMAP.md — нижче список того, що реально є.

Джерело істини — [PROJECT.md](../../PROJECT.md) §4 (фізична модель) і §9
(стиль C). Цей файл — покажчик по коду, не заміна.

## Що реалізовано (файл → що робить)

| Файл | Що |
|---|---|
| `vec3.c/h` | `Vec3d`, `vec3_sum_ordered` — сума у **фіксованому порядку**, бо порядок підсумовування — частина детермінізму (§4). |
| `cheb.c/h` | Обчислення чебишевських поліномів (`cheb_eval`, `cheb_eval_deriv`) — те, чим читається кукований ассет ефемериди й обертання тіл. |
| `ephemeris.c/h` | Завантаження скукованого ассета, `eph_body_state`, `eph_body_count`, `eph_body_name`, `eph_body_mu`, `eph_span`. Земля–Місяць–Сонце, точкові маси, чебишевська апроксимація. |
| `accel.c/h` | Задача двох тіл: `accel_two_body`, енергія, момент імпульсу, період — еталон для перевірки інтеграторів. |
| `integrator.h` + `rk4.c` + `dop853.c` | **DOP853 — рантайм-інтегратор** (адаптивний крок, допуск у метрах, стан кроку в `Dop853State` для сейвів). RK4 — фіксований крок, лишається як незалежна друга реалізація для звірки, не для рантайму. `dop853_integrate_blocks` носить до 7 "блоків" одним набором кроків одразу — саме так рахується STM поряд з траєкторією (один інтегратор, один допуск, CLAUDE.md інваріант 5). `dop853_integrate_obs` додає спостерігача кроку (`StepObserver`): його кличуть після кожного прийнятого кроку, і він може зупинити прогін, не торкаючись арифметики — на цьому стоїть `prop.c`. |
| `cr3bp.c/h` | Константа Якобі, точки Лагранжа (`cr3bp_lagrange`), потенціал, гессіан, `accel_cr3bp`, крива нульової швидкості (`cr3bp_zvc_radius`, ROADMAP G4 — межа з `2Ω(r) < C`, сканом+бісекцією уздовж променя, напрям векторний бо файл без `libm`). |
| `quat.h` | **Кватерніони (ROADMAP K3a).** Усе інлайн, як `vec3.h`. `quat_rotate` (тіло-фіксована → інерціальна, розклад без повного кватерніонного множення), `quat_normalize` (для того, що прийшло з чебишевської підгонки й не точно одиничне), `quat_conjugate`. Лише `+ - * / sqrt`. |
| `offline/body_rotation.c/h` | **Модель IAU полюс+PM (ROADMAP K3a), OFFLINE.** `body_rotation_of(name, t)` → кватерніон, з `pck00011.tpc` NAIF (Земля, Місяць; інші тіла — тотожність, «не змодельовано»). Явна матриця (3-1-3, `mat3_mul`), не ручний символьний розклад — метод Шеппарда матриця→кватерніон. Перевірено проти напряму полюса (незалежна формула) і швидкості обертання, уже закомуленої в `data/horizons/obj_earth.txt`/`obj_moon.txt`. **K3b (ассет-формат, кукер, рантайм-читач) ще не зроблено** — нічого поки не читає обертання з ассета. |
| `harmonics.c/h` | **Гармоніки Пайнса (ROADMAP K1).** `harmonics_accel`/`harmonics_potential` — довільні degree/order, ненормовані `C_nm/S_nm`, ізольована математика без прив'язки до тіла (полюс/обертання — K2/K3). Похідна виведена й перевірена символьно проти класичної формули J2 у `test_harmonics.c`, не взята з довідника без звірки. |
| `stm.c/h` | Матриця переходу стану: одиничну (`stm_identity`), перевірку симплектичності (`stm_symplectic_defect`) — головний діагностичний інструмент, коли диференціальна корекція не збігається. |
| `richardson.c/h` | Аналітичне наближення halo-орбіти 3-го порядку (Richardson 1980) — старт для `correct.c`, коли каталожного розв'язку нема. Працює лише без `sin`/`cos`: фаза, яку воно оцінює, завжди рівно ±1 або 0. |
| `correct.c/h` | Диференціальна корекція halo-орбіт: `halo_correct` (одна орбіта), `halo_family` (сімейство продовженням). Симетрія відносно xz-площини, два невідомих замість шести. |
| `shooting.c/h` | **Multiple shooting** (C4) — траєкторія у нестійкому регіоні (біля L2 збурення множиться на ~150–600 за оберт, `test_stability.c`) не рахується з одного кінця. Ланцюжок станів, неперервність вирішується глобально. Потрібне масштабування (метри/м-с) — без нього `J·Jᵀ` розсипається на 10 порядків. |
| `station.c/h` | Бюджет утримання станції: скільки Δv коштує лишатися на нестійкій орбіті, з горизонтом прицілювання. Те, що PROJECT.md §8 хоче показувати гравцю. Внутрішній прицільник винесено в `target.c` (ROADMAP G3). |
| `target.c/h` | **Диференціальна корекція для флайт-планера (M3, ROADMAP G3).** `target_hit` — Ньютон на 3×3 блоці STM (позиція-від-швидкості), одна ціль. Спільний з `station.c` (винесено звідти без зміни хешів). Верхній рівень `core/`, не `core/planning/`: жодної тригонометрії, лишається в детермінованій зоні, хоча один із викликачів (уточнення Lambert) сам поза межею. |
| `uncertainty.c/h` | Лінійне поширення коваріації (`P' = Φ P Φᵀ`) через уже наявну STM — прототип механіки невизначеності (PROJECT.md §8, ROADMAP «Прототип механіки невизначеності»). Прохід трекінгу — один коефіцієнт стиснення (`uncertainty_scale`), не модель вимірів. Лише `+ - * /` і `sqrt`. |
| `prop.c/h` | **Пропагатор за межею (ROADMAP H1–H2).** `prop_create`/`prop_free`/`prop_run` — апарат у полі всіх тіл ассета, семпли на **прийнятих кроках** (не на сітці: примусові приземлення забирають крок у контролера — виміряно на кукері), заповнений буфер як причина зупинки, крок інтегратора через `in_out_step` (він у сейві). Події (`CoreEvent`: перицентр, апоцентр, відстань від центра тіла) зупиняють прогін **рівно на події**, з safeguarded Ньютоном у брекеті. Подія, на якій прогін стартував, не спрацьовує повторно — класифікація `|g| < 1e-12·scale`, не поріг. Це єдиний файл, який викликає гра для руху апарата. |
| `field.c/h` | Гравітаційне поле ефемериди, як його відчуває корабель: `field_all_bodies`/`field_all_but`, `accel_field`. **Ще лише точкові маси** — `harmonics.c` (K1) дає математику гармонік, але сюди її ще не підключено (K4), бо для цього спершу потрібен полюс тіла (K2/K3); SRP і опір приїдуть пізніше в M3.5. Інтерфейс (`AccelFunc`) уже розрахований на розширення. |
| `frame.c/h` | Перетворення інерціальна ↔ обертова (синодична) система координат. |
| `hash.c/h` | `core_hash_*` — бітовий хеш стану для регресійних тестів детермінізму. |
| `refdata.c/h` | Читання еталонних GM з `data/` для звірки з JPL Horizons. |
| `offline/` | Кукер: `eph_build`, `cheb_fit`, `nbody` — рахує ефемериду й записує ассет. Не рантайм-код, окремий шлях виконання (`make cook`). **`nbody.c/h` з ROADMAP K2 несе J2 Землі** (`NBodySystem::has_j2/j2_body/j2_field`, `HarmonicsField` з `harmonics.c`) — реципрокна сила (Ньютонів третій закон явно) і відповідний доданок у `nbody_energy`. Полюс = вісь z рамки (K3 ще не приїхав); Місяць без гармонік (K5, реальні дані GRAIL, не вигадані числа). Вмикає `core/cook/cook_fixture.c`; `core/export/ex_ephspan.c` тримає той самий виклик, щоб міряти ефект. |
| `planning/lambert.c/h` | **Планування (M3, ROADMAP G1).** `lambert_solve` — швидкості переходу з r1 у r2 за час dt. Рантайм, але поза межею детермінізму (PROJECT.md §4: межа — по пропагації, не по плануванню), тому тут дозволений `libm` — третя бібліотека в графі збірки (`libcore_planning.a`), `scripts/check_no_libm.sh` свідомо її не сканує. Лише `n_revs = 0`. FFI на межу C↔Rust ще не оголошено. |
| `planning/porkchop.c/h` | **Планування (M3, ROADMAP G2).** `porkchop_compute` — сітка (час старту × час польоту) з Lambert на кожну клітинку, для UI вибору вікна (PROJECT.md §8). `BodyStateFunc` — приймач ефемериди через вказівник на функцію, як `AccelFunc`. Той самий підкаталог/бібліотека, що lambert.c. FFI ще не оголошено. |
| `export/` | CSV-експортери для `make csv`/`make plots` — діагностика, не частина гри. |

## Жорсткі інваріанти (тут, а не тільки в CLAUDE.md)

1. **У циклі інтегрування — лише `+ - * /` і `sqrt`.** Жодного `libm`:
   `sin/cos/exp/pow/atan2` бітово не гарантовані між платформами. `richardson.c`
   і `station.c` явно документують, чому в них теж немає `libm`, хоч це
   рантайм-код планування, не пропагація.
2. **`-ffp-contract=off`, ніякого `-ffast-math`.** Прапорці — в
   [core/cflags.txt](../../core/cflags.txt), **єдине місце**: і `make`, і
   `core-sys/build.rs` читають рівно його. Розбіжність між ними — це не
   помилка компіляції, а тиха зміна останніх бітів.
3. **Без `-lm`.** `-fno-math-errno` дозволяє апаратний `sqrt` без лінковки
   libm; сценарії детермінізму лінкуються без `-lm` навмисно як "поліція
   libm" (`make check-libm`) — якщо хтось випадково викликав функцію з libm,
   лінковка впаде.
4. **Один інтегратор, один допуск для прогнозу й фізики** (CLAUDE.md
   інваріант 5) — `dop853_integrate_blocks` з цієї ж причини носить STM
   разом з траєкторією, а не окремим проходом.
5. **Без глобального стану, без алокацій у гарячому циклі** (CLAUDE.md,
   «Стиль C»).

## Тести й перевірка

```sh
make test              # check-libm + unit (core/test/*.c) + determinism (хеш проти core/scenario/golden.txt)
make csv && make plots # діагностичні графіки з build/csv/*.csv (потрібен matplotlib)
make cook               # перегенерувати ассет-фікстуру — робити свідомо, воно комітиться
make flags               # прапорці, якими компілюється ядро — звірка з тим, що бачить cargo
```

Юніт-тести — `core/test/test_*.c`, кожен окремий бінарник (`core/test/test.h`
— мінімальний харнес). Сценарії детермінізму — `core/scenario/sc_*.c`,
еталон — `core/scenario/golden.txt`; `make determinism-bless` перегенеровує
еталон свідомо, коли зміна хешів — очікувана.

Тест на нестійкість (`test_stability.c`) — не «показник поганого коду»:
halo-орбіти лінійно нестійкі за конструкцією, і зростання збурення там —
вимірюваний факт (показник Ляпунова), а не привід шукати баг.

## Коли оновлювати цей скіл

- Змінився публічний інтерфейс будь-якого `core/*.h` (нова функція, інша
  сигнатура) — онови таблицю файлів вище.
- ROADMAP.md позначив новим ✅ крок етапу C, або почався M3.5 (гармоніки
  Пайнса, SRP, атмосферний опір у `field.c`) — це змінить рядок `field.c/h`
  з «лише точкові маси» на щось більше.
- Змінився `core/cflags.txt` — звір розділ «Жорсткі інваріанти» з файлом
  напряму, не покладайся на цей опис.
- З'явився новий `core/scenario/sc_*.c` або `core/test/test_*.c` —
  необов'язково описувати кожен, але якщо він перевіряє новий інваріант
  (не просто ще один сценарій для регресії), варто рядок сюди додати.
