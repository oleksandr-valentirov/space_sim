# game-sim

Етап **J закрито повністю** (стор ланок, курсор і warp, план з каскадним
перерахунком, нитки симуляції й планувальника, сейв), а поверх нього стоїть
інтерфейс **U1–U6**: HUD, розклад подій, редактор маневрів, porkchop-плот,
карта в обертовому фреймі з кривими нульової швидкості.

Джерело істини — [PROJECT.md](../../PROJECT.md) §6 (модель потоків),
[ROADMAP.md](../../ROADMAP.md) («Гра й потоки») і
[ROADMAP-UI.md](../../ROADMAP-UI.md) (рішення інтерфейсу).

## Рішення, з якого випливає решта

> **Годинник не входить в інтегратор.**

Майбутнє рахується **до** того, як до нього дійде час; курсор лише повзе по
вже порахованій ламаній. Тому фіксований крок симуляції не потрібен, а
частота кадрів не може змінити жодного біта траєкторії.

Умова, за якої це правда, — **інваріант 9**: `t_end` у `prop_run` ніколи не
походить від годинника, обсяг роботи міряється **ланками**. Найочевидніша
реалізація горизонту («тридцять діб уперед від зараз») цей інваріант
порушує, і J2 виміряв, що тоді ламається: три перевірки частоти кадрів, дві
з них навіть на кількості семплів.

## Ланка — одиниця всього

Один виклик `prop_run` = одна `Leg`. Вона ж одиниця поділу зі снапшотом
(`Arc<Leg>`), інвалідації при правці плану, відвантаження вершин на GPU і
зернистості сейву.

```
leg.rs      Sample, Leg { entry, t1, step_out, samples }, Trajectory, restart_at, Ерміт,
            retire_before — пенсія ланок позаду вікна курсора (N3a)
thin.rs     Дуглас-Пекер: індекси, без яких ламана не зміниться понад допуск
trail.rs    кеш прорідженого сліду на ланку; ключ — адреса Arc<Leg>, запис
            тримає той самий Arc
clock.rs    курсор, warp, пауза, Stall; годинник назад не ходить
plan.rs     Manoeuvre { t, dv, frame }, Plan, Frame::{Inertial, Vnb{body}}, diverges_from
world.rs    Vessel, World::step (тік + курсор), commit_plan, LEG=256, LEAD_LEGS=4
snapshot.rs WorldSnapshot — незмінний зріз; історія й прогноз це ОДНІ ланки
sim.rs      нитка симуляції: Command каналом, WorldSnapshot через arc-swap
planner.rs  нитка планувальника: спекулятивні прогони, скасування між ланками
save.rs     сейв: курсор + межа ланки + крок + план + applied; біти, не десяткові
view.rs     снапшот → engine::scene::Scene (уся межа гра↔рушій); build_thinned —
            проріджений слід через trail::Cache (N2b)
frame_view.rs вибір фрейму: інерціальний / синодичний, перетворення на CPU у f64
schedule.rs сканування ланок на події для ока (перицентр, апоцентр) — без озброєння
node.rs     вузли маневрів у сцені, піккінг проєкцією і ручки VNB
porkchop.rs розгортка сітки над lambert_solve: від апарата, у координатах центрального тіла
zvc.rs      криві нульової швидкості променями від кожного тіла
hud.rs      панелі: час, апарат, план, розклад, VIEW; повертають команди, не надсилають
text.rs     таблиця рядків, fn tr(key) — з першої панелі, англійська основна
app.rs      цикл winit; світ не рахує й не чіпає — читає
mission.rs  що саме запускається: halo 1151, 101.79 доби, warp 1e5; fleet() —
            halo плюс N станцій на 600-1300 км, фікстура етапу N
```

## Дві поля, які легко пропустити й дорого додавати потім

- **`Leg::step_out`** — крок, з яким прогін залишив ланку. Без нього
  перезапуск із середини неможливий, тобто немає ні каскадного перерахунку,
  ні сейву. H1 виміряв ціну: ×70 роботи й інша траєкторія.
- **`Leg::entry`** — стан, з якого ланка почалася. Після маневру це стан
  **після** імпульсу, тоді як останній семпл попередньої ланки — до нього.
  Без цього Ерміт згладив би розрив швидкості.

## Що ходить каналом, а що снапшотом

Неперервний стан — снапшотом, дискретна подія — каналом. Снапшот це
вибірка: читач, що пропустив публікацію, пропустив би подію назавжди.

**Наслідок, який не очевидний:** озброєна подія (`Event::Periapsis` тощо)
зупиняє прогін і змінює послідовність кроків після неї (H2). Тому
озброюються **лише** події, потрібні плану; маркери для ока шукаються
скануванням уже порахованих семплів.

## Виміряні числа — не переоткривати

| Що | Скільки | Де |
|---|---|---|
| Читання снапшоту при насиченій нитці | 13.8 мкс найгірше, 1.9 млн за 300 мс | J4 |
| Ерміт проти прямої, посередині між кроками | **17.4 км** | J2 |
| Ланка при `LEG=256` на halo-орбіті | ~11 діб траєкторії | J2 |
| Кадр на стелі warp (10⁷) | 1.85 доби | J2 |
| Скидання кроку на маневрі | +1.4% роботи (365 → 370 кроків) | J3 |
| Скидання кроку в сейві | інша гра (1832 → 1836 семплів) | J6 |
| Каскад: правка на 25-й добі при курсорі на 20-й | 3 ланки з 5 перераховано, 605 семплів збережено | J3 |

**Warp на вільному польоті в пропускну здатність не упирається**:
інтегратор випереджає годинник ушестеро навіть на стелі й з однією ланкою на
кадр. Упреться на тязі та в атмосфері, де крок фіксований і малий.

## Пастки, кожна знайдена, а не передбачена

1. **Тік мусить рахувати поступ, а не спробу.** Апарат, який не рухається,
   інакше зациклює прогін **назавжди** — і зависання читається як «щось
   задумалось», а не як помилка. Знайдено перевіркою зубів J3.
2. **Сейв зберігає курсор, а не горизонт.** Перша версія зберігала `tip`, і
   завантажена гра стрибала з 30-ї доби на 66-ту.
3. **Чекати в тесті треба на слід нової роботи, а не на кількість.**
   Перевірка J5 «доки не стане дві ланки» проходила **до** коміту плану: цих
   ланок і так уже було досить. Ознака мусить бути такою, якої не могло бути
   раніше.
4. **`applied` зберігається числом.** Стан до й після імпульсу мають
   однаковий час, тож вивести його з часів неможливо без двозначності.

## Пенсія ланки — двері в один бік (N3a)

Ланка, що відійшла від курсора далі ніж на `RAW_LEGS_BEHIND`, проріджується
**раз і назавжди** до `RETIRE_TOL_M` = 8·10⁵ м. Недоторканні `entry`,
останній семпл і `step_out` — на них стоїть сейв.

Це **політика**, а не поведінка: `World::set_retirement(None)` вимикає її.
Вимикають двоє — спекулятивний світ планувальника й будь-який тест, що звіряє
потік семплів із незалежним прогоном (`plan.rs`, `trajectory.rs`,
`schedule.rs`, `trail.rs`). Пенсія не міняє жодного біта того, що порахували,
але міняє те, що лишилось.

Наслідок, який легко не помітити: маркери подій **у минулому** грубішають —
скан перицентра дає 395 с розбіжності проти озброєної події замість 60.

## Команди

```sh
cargo run -p game                                   # вікно
cargo run -p game -- --demo-plan                    # з показовим маневром
cargo run -p game -- --shot build/x.png --day 40    # кадр, курсор на 40-й добі
cargo run -p game -- --shot build/x.png --save build/j6.save
cargo run -p game -- --load build/j6.save
cargo run --release -p game -- --perf-probe 101 --stations 30   # флот, етап N
cargo test -p game                                  # усі перевірки етапу J
```

У вікні: пробіл — пауза, «.» і «,» — warp, «p» — прев'ю маневру, Enter —
летіти ним, F5 — сейв.

## Коли оновлювати цей скіл

- Змінилися `LEG` чи `LEAD_LEGS` — числа в таблиці вище прив'язані до них.
- Змінився допуск пенсії (`world::RETIRE_TOL_M`) чи вікно
  (`RAW_LEGS_BEHIND`) — від них залежать усі числа етапу N.
- Змінилося вікно історії (`world::HISTORY_REVOLUTIONS`, типово 20 обертів) —
  від нього залежить усе, що етап N виміряв про пам'ять і кадр.
- З'явилася тяга в C — скінченні горіння змінять `plan.rs`, і зерно
  «імпульс» стане окремим випадком.
