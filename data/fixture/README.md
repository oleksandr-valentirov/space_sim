# Ассети-фікстури

## `earth_moon.eph`

Скукована ефемерида, **закомічена навмисно**, попри те що
`.gitignore` загалом виключає `*.eph`.

## Навіщо

Сценарії детермінізму (`core/scenario/`) лінкуються тільки з `libcore.a` і без
`-lm` — це жива перевірка того, що в рантайм не просочилася тригонометрія.
Отже сценарій **не може скукати ассет сам**: чебишевська підгонка використовує
`cos()`.

Але без ассета крос-платформна звірка (ROADMAP C5) не покриває рантаймовий
шлях: читання коефіцієнтів, поле тяжіння, синодичну систему, multiple shooting.
Саме той шлях, від якого залежить гра.

І є друга, важливіша причина не генерувати його на кожній платформі: кукер
рахує коефіцієнти через `cos()`, а `cos()` бітово не гарантований між
бібліотеками. Дві машини скукали б **різні** ассети, і звірка падала б на
кукері замість рантайму, який вона має перевіряти.

Це не обхідний шлях, а сама архітектура: PROJECT.md §4 каже, що кукер
працює один раз на машині розробника, а результат їде в білд.

## Що всередині

| | |
|---|---|
| Тіла | усі 10 великих: Сонце, Меркурій, Венера, Земля, Місяць, баріцентри Марса, Юпітера, Сатурна, Урана, Нептуна |
| Проміжок | 120 діб від J2000 TDB, 15 інтервалів по 8 діб |
| Ступінь | 14 коефіцієнтів на компоненту |
| Розмір | 50848 байт |
| Похибка підгонки | 4.62e-2 м |

Початкові умови — з `data/horizons/`, допуск інтегрування 1e-6 м.

Допуск обирався двічі. Спершу за найшвидшим тілом, не за розміром системи
(ROADMAP B5) — звідти був метр. Потім `core/export/ex_ephspan.c` показав,
що метр тут **не діє взагалі**: кроки задають примусові приземлення на вузли
чебишевської підгонки, і при 1, 0.1 та 0.01 м кук робив однакову кількість
кроків. Точність виходила з кадансу вузлів, а зміна `INTERVAL_DAYS` чи
`DEGREE` тихо змінила б її, нічого не повідомивши. Тепер допуск обмежує сам:
кроків 526 замість 350, значення ассета зрушили щонайбільше на 2.2 см
(Місяць) — менше за похибку підгонки, тобто фізика та сама.

**Баріцентр закріплено.** Початкові умови десяти тіл несуть залишковий
імпульс — 3.35 мм/с швидкості баріцентру, бо набір неповний. Кукер віднімає
її з усіх тіл (`nbody_anchor_barycentre`) перед першим кроком; без цього
вся система рівномірно повзла б крізь кадр, 1.05·10⁶ м за 10 років. Це
чистий перенос: усі десять тіл зрушили однаково, на 3.474·10⁴ м за 120 діб,
взаємна геометрія недоторкана.

Вимкнути для порівняння — `make cook ANCHOR_BARYCENTRE=0`. Робити лише
свідомо: ассет, що їде в гру, анкерований.

## Як перегенерувати

```
make cook
```

Робити свідомо: це змінює хеші `sc_ephemeris` і `sc_trajectory`, тож після
цього потрібен `make determinism-bless`, і різницю треба показати в коміті.

## `halo_inertial.csv`

Halo-траєкторія з C4 (орбіта каталогу 1151, перенесена в реальну ефемериду
й зшита multiple shooting), для `engine::trajectory` (ROADMAP F6). Урізана
версія `build/csv/halo_inertial.csv` з `core/export/ex_trajectory`: прибрано
лише `days` (похідне від `t`), лишилось 16 стовпців із 17.

**`vx,vy,vz` спершу прибирали, а на H5 повернули.** Аргумент «рушію лінія без
швидкостей» був правдивий рівно доти, доки рушій лінію лише читав. З H5 він
її рахує: `engine::live` бере з першого рядка **стан** і веде його далі через
`prop_run`. Позиція без швидкості — не стан, і продовжити її неможливо.

### Навіщо саме тут, а не через FFI

⚠ **Застаріло з H5: рушій уже лінкує `core-rs`.** Файл лишається — але тепер
як **еталон**, а не як єдине джерело лінії: `engine/tests/live.rs` кладе
поруч із ним траєкторію, пораховану зараз, і міряє, як довго вони
тримаються разом. Текст нижче — історія рішення.

Рушій (`/engine`) не лінкує `core-rs` — це окреме, більше архітектурне
рішення (справжній зв'язок фізики й рендера), не те, що варто робити
попутно з кроком про рендер-техніку. Тому дані приходять готовим ассетом,
той самий принцип, що `earth_moon.eph`: кукер (тут — `ex_trajectory`)
рахує один раз, результат комітиться.

### Що всередині

| | |
|---|---|
| Семплів | 1345, орбіта 1151, 7 обертів (~102 доби) |
| `t` | секунди від епохи ассета |

| Розмір | ~335 КБ |

### Як перегенерувати

```
make csv
awk -F, 'BEGIN{OFS=","} NR==1{print "t","x","y","z","earth_x","earth_y","earth_z","moon_x","moon_y","moon_z","sx","sy","sz"; next} {print $1,$3,$4,$5,$9,$10,$11,$12,$13,$14,$15,$16,$17}' build/csv/halo_inertial.csv > data/fixture/halo_inertial.csv
```

Стовпці `build/csv/halo_inertial.csv` — `t,days,x,y,z,vx,vy,vz,earth_x,earth_y,earth_z,moon_x,moon_y,moon_z,sx,sy,sz`
(`core/export/ex_trajectory.c`), звідси й номери полів в `awk`.
