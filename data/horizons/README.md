# Еталонні дані JPL Horizons

Оракул, відносно якого вимірюється власне ядро (ROADMAP B1). Дані статичні;
вивантажені один раз скриптом [`scripts/fetch_horizons.sh`](../../scripts/fetch_horizons.sh)
і закомічені навмисно — щоб тести не залежали від мережі й від того, чи
змінився API.

## Параметри запиту (частина контракту даних)

| Параметр | Значення | Чому саме так |
|---|---|---|
| `CENTER` | `500@0` — барицентр Сонячної системи | PROJECT.md §4: барицентрична інерціальна |
| `REF_PLANE` + `REF_SYSTEM` | `FRAME` + `ICRF` | Екваторіальна ICRF, **не екліптика** |
| `OUT_UNITS` | `KM-S` | У метри конвертує завантажувач |
| `VEC_CORR` | `NONE` | Геометричні вектори, без світлової затримки й аберації |
| Час | JDTDB | Барицентричний динамічний, без високосних секунд |
| Інтервал | 2000-01-01 12:00 .. 2010-01-01 12:00 | 10 років для регресії B5 |
| Крок | 30 діб | 122 точки на тіло |
| Джерело | DE441 | Повідомляє сам Horizons |

Зміна будь-чого з цього робить дані несумісними з попередніми. Більшість
розбіжностей у чисельних задачах народжується саме тут, а не у фізиці.

## Файли

- `vec_<тіло>.csv` — `jdtdb,x_km,y_km,z_km,vx_kms,vy_kms,vz_kms`
- `obj_<тіло>.txt` — сира сторінка параметрів тіла з Horizons (походження GM)
- `gm.csv` — `name,gm_km3_s2`, витягнуто з `obj_*.txt`

Тіла: `sun`, `earth`, `moon` — для M0. `venus`, `mars_bary`, `jupiter_bary` —
наперед, для гілки розвилки B5 («додавайте збурення по одному»).

## Відкрите питання: GM барицентрів

`mars_bary` і `jupiter_bary` — це вектори **барицентрів** систем (COMMAND=4
і 5), але GM у `gm.csv` для них узято зі сторінок **планет** (499 і 599).
Барицентр — динамічна точка, власного GM Horizons для нього не публікує.

Для Марса різниця нехтовна (Фобос і Деймос мікроскопічні). Для Юпітера
галілеєві супутники дають близько 0.02% — це помітно, якщо колись знадобиться
точність краща за цю величину.

**Не вигадувати число.** Коли дійде до гілки B5 з додаванням Юпітера, взяти
системний GM з окремого джерела (наприклад заголовка ядра DE441) або
підсумувати GM планети й супутників з Horizons.

## Повторне вивантаження

```sh
sh scripts/fetch_horizons.sh
```

Потреби немає: дані незмінні. Скрипт існує заради відтворюваності
й документування запиту.
